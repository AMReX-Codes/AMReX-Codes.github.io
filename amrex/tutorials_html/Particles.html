Particles

These tutorials use AMReX particle containers: pure struct-of-arrays (SoA) particle data distributed over the same grids as mesh data, particle-mesh deposition and gather, particles on an AMR hierarchy, tracer particles around an embedded boundary, sorting and filtering within tiles, neighbor lists, and a complete particle-in-cell code. All of them require AMReX built with particles (AMReX_PARTICLES, on by default); EBTracers also needs EB and the linear solvers, and ElectrostaticPIC the linear solvers. EBTracers, NeighborList and ElectrostaticPIC run in 2D and 3D only. Build only this topic with -DAMReXTutorials_TOPICS=Particles; see Getting Started.

Particles/Basics

Key APIs:

ParticleContainerPureSoA, SetSoACompileTimeNames, AddRealComp, DefineAndReturnParticleTile, ParticleTileData, SetParticleIDandCPU, ParIter, Redistribute, ReduceSum, Increment, WritePlotFile, Checkpoint, Restart

A first particle code. Each particle stores its position, velocity and weight as separate arrays; the first AMREX_SPACEDIM real components are the positions. A component dist (distance traveled) is added at run time. Particles are created on the device with nppc random particles per cell, move in straight lines through a periodic domain, and are moved to their new grid and MPI rank by Redistribute. ReduceSum computes the total weight and kinetic energy. The program writes a plotfile with the particle count per cell and the particles, and a particle checkpoint that it reads back with Restart.

The test checks that the number of particles, total weight and kinetic energy are conserved.

The components are named with an enum; the container stores all of them, including the positions and the id/cpu word, as separate arrays.

// Real components of each particle. In a pure struct-of-arrays (SoA)
// container, the first AMREX_SPACEDIM real components are the positions.
struct RealIdx
{
    enum {
        AMREX_D_DECL(x, y, z),
        AMREX_D_DECL(vx, vy, vz),
        w,      // weight, e.g., mass
        ncomps
    };
};

// All components, including position and id/cpu, are stored as separate arrays.
using PC = amrex::ParticleContainerPureSoA<RealIdx::ncomps, 0>;
using ParticleType = PC::ParticleType;

Each tile is filled directly on the device. A block of unique ids is reserved per tile, and ParallelForRNG provides a random engine.

// Reserve a block of unique particle ids on this process.
const amrex::Long id0 = ParticleType::NextID();
ParticleType::NextID(id0 + np);

// DefineAndReturnParticleTile also allocates the runtime components.
auto& tile = pc.DefineAndReturnParticleTile(lev, mfi);
tile.resize(np);
auto ptd = tile.getParticleTileData();

amrex::ParallelForRNG(np,
[=] AMREX_GPU_DEVICE (amrex::Long ip, amrex::RandomEngine const& engine) noexcept
{
    const amrex::IntVect iv = bx.atOffset(ip / nppc);
    ptd.idcpu(ip) = amrex::SetParticleIDandCPU(id0 + ip, myproc);
    for (int d = 0; d < AMREX_SPACEDIM; ++d) {
        ptd.pos(d, ip) = static_cast<amrex::ParticleReal>(
            plo[d] + (iv[d] + amrex::Random(engine)) * dx[d]);
        ptd.rdata(RealIdx::vx+d)[ip] = static_cast<amrex::ParticleReal>(
            vmax * (2.0_rt*amrex::Random(engine) - 1.0_rt));
    }
    ptd.rdata(RealIdx::w)[ip] = static_cast<amrex::ParticleReal>(
        0.5_rt + amrex::Random(engine));
    ptd.m_runtime_rdata[0][ip] = 0;
});

The push loops over the particle tiles with ParIter. Particles move less than one cell per step, so Redistribute only communicates with neighboring ranks.

for (PC::ParIterType pti(pc, lev); pti.isValid(); ++pti)
{
    const int np = pti.numParticles();
    auto ptd = pti.GetParticleTile().getParticleTileData();
    // Components can also be looked up as arrays, e.g., by index or by name.
    amrex::ParticleReal* dist = pti.GetStructOfArrays().GetRealData(dist_comp).data();

    amrex::ParallelFor(np, [=] AMREX_GPU_DEVICE (int i) noexcept
    {
        amrex::ParticleReal v2 = 0;
        for (int d = 0; d < AMREX_SPACEDIM; ++d) {
            const amrex::ParticleReal v = ptd.rdata(RealIdx::vx+d)[i];
            ptd.pos(d, i) += static_cast<amrex::ParticleReal>(v * dt);
            v2 += v*v;
        }
        dist[i] += static_cast<amrex::ParticleReal>(std::sqrt(v2) * dt);
    });
}

// Particles moved less than one cell, so only neighboring ranks need to
// communicate (local = 1). Redistribute also applies periodic wrapping.
pc.Redistribute(0, -1, 0, 1);

ParticleMesh

Level:

★★

Source:

Particles/ParticleMesh

Key APIs:

ParticleToMesh, MeshToParticle, ParticleInterpolator::Linear, InitRandom, ReduceSum, ReduceMax, WritePlotFile

Deposit a particle quantity onto the mesh and gather a mesh field to the particles with cloud-in-cell (linear) weights. In 1D, a particle at \(x\) between the cell centers \(x_i\) and \(x_{i+1}\), with \(f = (x - x_i)/\Delta x\), gives a fraction \(1-f\) of its mass to cell \(i\) and \(f\) to cell \(i+1\); the gather uses the same weights. In 2D and 3D the weights are products of the 1D weights.

The particles and the mesh use different BoxArrays (particle_max_grid_size and max_grid_size); ParticleToMesh and MeshToParticle copy data between the two layouts. The test checks that the deposited mass equals the total particle mass and that the gather reproduces a linear field to round-off.

The deposition callable runs once per particle and adds its weighted contributions with atomic adds. Contributions to ghost cells are summed into the valid cells that own them, including across periodic boundaries.

// Deposit the mass density with cloud-in-cell (linear) weights. A
// particle touches 2^AMREX_SPACEDIM cells, so rho needs one ghost cell;
// ParticleToMesh sums ghost cell contributions into the valid cells.
amrex::MultiFab rho(mesh_ba, mesh_dm, 1, 1);
amrex::ParticleToMesh(pc, rho, 0,
    [=] AMREX_GPU_DEVICE (const ConstPTD& ptd, int i,
                          amrex::Array4<amrex::Real> const& rho_arr) noexcept
    {
        const ConstParticle p = ptd[i];
        amrex::ParticleInterpolator::Linear interp(p, plo, dxi);
        // The callable returns the value to deposit (uses atomic adds).
        interp.ParticleToMesh(p, rho_arr, 0, 0, 1,
            [=] (ConstParticle const&, int) noexcept
            {
                return ptd.rdata(RealIdx::mass)[i] * inv_cell_volume;
            });
    });

The gather needs a mesh field with filled ghost cells. The first callable reads the mesh, the second accumulates each weighted value on the particle.

// Gather the field to the particles with the same linear weights.
amrex::MeshToParticle(pc, efield, 0,
    [=] AMREX_GPU_DEVICE (const PTD& ptd, int i,
                          amrex::Array4<const amrex::Real> const& e_arr) noexcept
    {
        auto p = ptd[i];
        for (int d = 0; d < AMREX_SPACEDIM; ++d) {
            ptd.rdata(RealIdx::Ex+d)[i] = 0;
        }
        amrex::ParticleInterpolator::Linear interp(p, plo, dxi);
        // The first callable reads the mesh, the second updates the
        // particle with each weighted contribution.
        interp.MeshToParticle(p, e_arr, 0, 0, AMREX_SPACEDIM,
            [=] (amrex::Array4<const amrex::Real> const& arr,
                 int ii, int jj, int kk, int comp) noexcept
            {
                return arr(ii, jj, kk, comp);
            },
            [=] (PC::ParticleType&, int comp, amrex::Real val) noexcept
            {
                ptd.rdata(RealIdx::Ex+comp)[i] += static_cast<amrex::ParticleReal>(val);
            });
    });

MultiLevel

Level:

★★★

Source:

Particles/MultiLevel

Key APIs:

ParticleContainerPureSoA(geom, dmap, ba, rr), NumberOfParticlesAtLevel, ReduceSum(pc, lev, f), Redistribute, ParIter(pc, lev), multi-level ParticleToMesh, SetParticleBoxArray, SetParticleDistributionMap, WriteMultiLevelPlotfile, WritePlotFile

Particles on an AMR hierarchy. A container defined on several levels keeps each particle on the finest level that covers it. On a fixed two-level hierarchy (level 1 refines the middle half of the periodic domain in each direction), the program initializes random particles, deposits their weights on both levels, moves the particles across the coarse/fine boundary, and regrids level 1, which is what an AmrCore code does when its grids change.

The container takes the Geometry, DistributionMapping and BoxArray of every level and the refinement ratios; a code built on AmrCore uses AmrParticleContainer, which takes them from the AmrCore. InitRandom and Redistribute place each particle on the finest level whose grids cover it, which the program checks on every level:

// Every particle must be on the finest level that covers it: all level-1
// particles inside the fine region, no level-0 particle inside it.
bool check_levels (PC const& pc, amrex::Box const& region)
{
    amrex::Long const n0 = pc.NumberOfParticlesAtLevel(0);
    amrex::Long const n1 = pc.NumberOfParticlesAtLevel(1);
    amrex::Long const in0 = count_in_region(pc, 0, region);
    amrex::Long const in1 = count_in_region(pc, 1, region);
    amrex::Print() << "  level 0: " << n0 << " particles, " << in0 << " under level 1; "
                   << "level 1: " << n1 << " particles, " << in1 << " in its region\n";
    return in0 == 0 && in1 == n1;
}

The multi-level ParticleToMesh deposits on every level and takes care of the coarse/fine boundaries, so that the integral of the level-0 density is the total weight. The callable receives the plo and dxi of the level it deposits on:

void deposit (PC const& pc, amrex::Vector<amrex::MultiFab>& rho)
{
    amrex::ParticleToMesh(pc, amrex::GetVecOfPtrs(rho), 0, int(rho.size())-1,
        [=] AMREX_GPU_DEVICE (ConstPTD const& ptd, int i, amrex::Array4<Real> const& rho_arr,
                              amrex::GpuArray<Real,AMREX_SPACEDIM> const& plo,
                              amrex::GpuArray<Real,AMREX_SPACEDIM> const& dxi) noexcept
        {
            auto const p = ptd[i];
            amrex::ParticleInterpolator::Linear interp(p, plo, dxi);
            interp.ParticleToMesh(p, rho_arr, 0, 0, 1,
                [=] (PC::ParticleType::ConstType const&, int) noexcept
                {
                    return ptd.rdata(RealIdx::w)[i];
                });
        });
}

Particles are moved level by level, and Redistribute then handles the periodic boundaries, the grids, the MPI ranks and the levels at once. Regridding a level means giving the container the new grids and calling Redistribute; a container built from an AmrCore takes the new grids from it and only needs the Redistribute after regrid:

region.shift(0, n_cell/4);
grids[1].define(amrex::refine(region, ratio));
grids[1].maxSize(max_grid_size);
dmap[1] = amrex::DistributionMapping(grids[1]);
pc.SetParticleBoxArray(1, grids[1]);
pc.SetParticleDistributionMap(1, dmap[1]);
pc.Redistribute();

Particles/EBTracers

Key APIs:

mac_interpolate, FillSignedDistance, ParticleToMesh, ParticleInterpolator::Linear, ReduceSum over particles, MLEBABecLap

Tracer particles carry a scalar through a flow around an embedded boundary: each particle has a fixed weight, and depositing the weights on the mesh gives the scalar field. It is the Lagrangian counterpart of Advection, and builds the same kind of flow: a uniform velocity made to go around a sphere in a periodic domain with a MAC projection. The velocity is kept at face centers, where mac_interpolate expects it.

Each step moves the particles with the midpoint method, with the face velocity interpolated to the particles by mac_interpolate. The interpolation does not know about the EB, so a few particles near the sphere end up inside it, up to about a cell deep. They are reflected back across the EB using the signed distance s to the EB, filled on the nodes by FillSignedDistance: the depth is -s and the normal is the gradient of s. This works for any EB geometry.

// Inside the body (s < 0): move 2|s| along the normal grad(s)/|grad(s)|.
Real grad[AMREX_SPACEDIM];
const Real s = signed_distance(sda, p.x, plo, dxi, grad);
if (s < 0.0_rt) {
    Real gnorm = 0.0_rt;
    for (int d = 0; d < AMREX_SPACEDIM; ++d) { gnorm += grad[d]*grad[d]; }
    gnorm = std::sqrt(gnorm);
    if (gnorm > 0.0_rt) {
        for (int d = 0; d < AMREX_SPACEDIM; ++d) {
            p.x[d] += ParticleReal(-2.0_rt * s * grad[d] / gnorm);
        }
        ptd.idata(IntIdx::reflected)[i] += 1;
    }
}

The particles move forward to stop_time and back with the velocity reversed. The program checks that the deposited weight equals the total particle weight, and that the particles that were never reflected return, on average, to within 0.001 cells of where they started.

Sorting

Level:

★★

Source:

Particles/Sorting

Key APIs:

DenseBins, getParticleCell, SortParticlesByCell, SortParticlesByBin, partitionParticles, filterParticles, transformParticles, DefineAndReturnParticleTile

Organize the particles of a tile:

  1. DenseBins builds a counting sort of the particles by cell without moving them. permutationPtr() lists particle indices bin by bin and offsetsPtr()[b] is where bin b starts, so a kernel over cells can loop over the particles of each cell.

  2. SortParticlesByCell and SortParticlesByBin reorder the particle data so that particles in the same cell (or group of cells) are adjacent in memory, which improves memory access in deposition kernels.

  3. partitionParticles moves the particles that satisfy a predicate (here: speed above vcut) to the front of the tile.

  4. filterParticles copies the particles that satisfy a predicate to another tile, and transformParticles copies particles while changing them (here: reversing the velocity).

The test checks that the DenseBins counts match ParticleContainer::Increment and that the particles are in order after SortParticlesByCell.

Binning by cell and looping over the particles of each cell:

amrex::DenseBins<ConstPTD> bins;
for (PC::ParIterType pti(pc, lev); pti.isValid(); ++pti)
{
    // With particle tiling, a grid holds several tiles.
    const amrex::Box bx = pti.tilebox();
    const auto ptd = pti.GetParticleTile().getConstParticleTileData();
    const amrex::IntVect lo = bx.smallEnd();
    const auto domain_box = geom.Domain();
    // Map each particle to its cell, relative to the lower corner of bx.
    bins.build(pti.numParticles(), ptd, bx,
        [=] AMREX_GPU_DEVICE (const ConstPTD& p, int i) noexcept -> amrex::IntVect
        {
            return amrex::getParticleCell(p, i, plo, dxi, domain_box) - lo;
        });

    const auto* offsets = bins.offsetsPtr();
    auto const& cnt = count_bins.array(pti);
    amrex::ParallelFor(bx, [=] AMREX_GPU_DEVICE (int i, int j, int k) noexcept
    {
        const int b = static_cast<int>(bx.index(amrex::IntVect(AMREX_D_DECL(i, j, k))));
        // The particles in cell (i,j,k) are permutationPtr()[offsets[b]:offsets[b+1]].
        cnt(i,j,k) = amrex::Real(offsets[b+1] - offsets[b]);
    });
    amrex::Gpu::streamSynchronize(); // bins is reused for the next tile
}

Copying a subset of the particles, and transformed copies, into other containers. The destination tiles must be large enough.

PC slow_pc(geom, dm, ba);
PC reversed_pc(geom, dm, ba);
for (PC::ParIterType pti(pc, lev); pti.isValid(); ++pti)
{
    const auto& src = pti.GetParticleTile();
    const int np = src.numParticles();

    auto& slow = slow_pc.DefineAndReturnParticleTile(lev, pti);
    slow.resize(np);
    const int nslow = amrex::filterParticles(slow, src,
        [=] AMREX_GPU_DEVICE (const ConstPTD& ptd, int i) noexcept
        {
            amrex::ParticleReal v2 = 0;
            for (int d = 0; d < AMREX_SPACEDIM; ++d) {
                v2 += ptd.rdata(RealIdx::vx+d)[i] * ptd.rdata(RealIdx::vx+d)[i];
            }
            return v2 <= vcut2;
        });
    slow.resize(nslow);

    auto& reversed = reversed_pc.DefineAndReturnParticleTile(lev, pti);
    reversed.resize(np);
    amrex::transformParticles(reversed, src,
        [=] AMREX_GPU_HOST_DEVICE (const PTD& dst, const ConstPTD& s, int si, int di) noexcept
        {
            dst.idcpu(di) = s.idcpu(si);
            for (int d = 0; d < AMREX_SPACEDIM; ++d) {
                dst.pos(d, di) = s.pos(d, si);
                dst.rdata(RealIdx::vx+d)[di] = -s.rdata(RealIdx::vx+d)[si];
            }
        });
}

NeighborList

Level:

★★★

Source:

Particles/NeighborList

Key APIs:

NeighborParticleContainerPureSoA, fillNeighbors, updateNeighbors, buildNeighborList, NeighborList::data, getNeighbors, Redistribute, ReduceSum, ReduceMax, RandomNormal

A small molecular dynamics code with short-range forces. Particles are soft spheres of diameter \(\sigma\) with the potential \(U(r) = \frac{k}{2}(\sigma - r)^2\) for \(r < \sigma\).

MDParticleContainer derives from NeighborParticleContainerPureSoA. fillNeighbors copies particles within one cell of each tile (including periodic images) into that tile, after its real particles. buildNeighborList then lists, for each real particle, the nearby real and neighbor particles that pass a CheckPair test. The list radius is one cell, larger than \(\sigma\), so the list stays valid for num_rebuild steps; in between, updateNeighbors only refreshes the positions of the neighbor copies.

The test checks that the total momentum is conserved (pair forces are equal and opposite, also across tiles and MPI ranks) and that the relative change in total energy is below 1%.

The time loop uses velocity Verlet and rebuilds the neighbor list every num_rebuild steps:

// Velocity Verlet time stepping.
for (int step = 1; step <= nsteps; ++step)
{
    pc.kickDrift(0.5_rt*dt, dt);

    if (step % num_rebuild == 0) {
        // Particles moved less than one cell since the last rebuild.
        pc.Redistribute(0, -1, 0, 1);
        pc.fillNeighbors();
        pc.buildNeighborList(check_pair);
    } else {
        // Only refresh the data of the existing neighbor copies.
        pc.updateNeighbors();
    }

    pc.computeForces(params);
    pc.kickDrift(0.5_rt*dt, 0.0_rt);

The force kernel loops over the neighbors of each real particle:

// For each real particle i, the list holds the indices of nearby
// particles in this tile, which may be real particles or neighbor copies.
const auto nbor_data = m_neighbor_list[lev].at(index).data();

amrex::ParallelFor(np, [=] AMREX_GPU_DEVICE (int i) noexcept
{
    amrex::Real acc[AMREX_SPACEDIM] = {AMREX_D_DECL(0._rt, 0._rt, 0._rt)};
    amrex::Real pe = 0;
    for (const auto& p2 : nbor_data.getNeighbors(i))
    {
        amrex::Real dr[AMREX_SPACEDIM];
        amrex::Real r2 = 0;
        for (int d = 0; d < AMREX_SPACEDIM; ++d) {
            dr[d] = ptd.pos(d, i) - p2.pos(d);
            r2 += dr[d]*dr[d];
        }
        if (r2 >= sigma*sigma) { continue; }

        // Repulsive force k (sigma - r) along the unit vector dr/r.
        const amrex::Real r = amrex::max(std::sqrt(r2), 1.e-6_rt*sigma);
        const amrex::Real overlap = sigma - r;
        const amrex::Real coef = k * overlap / r;
        for (int d = 0; d < AMREX_SPACEDIM; ++d) {
            acc[d] += coef * dr[d];
        }
        // Each pair is visited from both sides; take half the energy.
        pe += 0.25_rt * k * overlap * overlap;
    }
    for (int d = 0; d < AMREX_SPACEDIM; ++d) {
        ptd.rdata(RealIdx::ax+d)[i] = static_cast<amrex::ParticleReal>(acc[d]);
    }
    ptd.rdata(RealIdx::pe)[i] = static_cast<amrex::ParticleReal>(pe);
});

ElectrostaticPIC

Level:

★★★ / Blueprint

Source:

Particles/ElectrostaticPIC

Key APIs:

ParticleContainerPureSoA, ParticleToMesh, MeshToParticle, ParticleInterpolator::Linear, MLPoisson, MLMG, ParReduce, Redistribute, WriteSingleLevelPlotfile, WritePlotFile

An electrostatic particle-in-cell (PIC) code for electrons moving through a fixed, neutralizing ion background in a periodic box, organized to be copied as the starting point of a PIC code. Each step:

  1. Deposit the electron charge with cloud-in-cell weights (ParticleToMesh) and add the ion charge.

  2. Solve \(\nabla^2\phi = -\rho/\epsilon_0\) with MLPoisson and MLMG, and compute \(E = -\nabla\phi\) at cell centers with centered differences.

  3. Interpolate \(E\) to the particles (MeshToParticle).

  4. Leapfrog push: \(v \mathrel{+}= (q/m) E\,\Delta t\), then \(x \mathrel{+}= v\,\Delta t\), then Redistribute.

The problem is a Langmuir (plasma) oscillation. In normalized units (\(\epsilon_0 = m = n_0 = 1\), \(q = -1\)) the plasma frequency is \(\omega_p = \sqrt{n_0 q^2/(\epsilon_0 m)} = 1\). The electrons start at rest, displaced by \(\xi_0 \sin(kx)\), and linear theory gives \(E_x = -(q n_0 \xi_0/\epsilon_0) \sin(kx) \cos(\omega_p t)\). The code measures the frequency from the zero crossings of the \(\sin(kx)\) mode of \(E_x\). It checks that the frequency agrees with theory to 2%, and that the total (field plus kinetic) energy changes by less than 2%.

The time loop in main.cpp:

// Charge deposition, field solve and gather at time t^n.
electrons.depositCharge(rho);
rho.plus(rho_ion, 0, 1, 0);
solver.solvePhi(phi, rho);
solver.computeE(efield, phi);
electrons.gatherField(efield);

// Leapfrog: velocities live at half steps. Start with v^{-1/2}.
if (step == 0) { electrons.pushVelocity(-0.5_rt*dt); }

Charge deposition in PICParticleContainer.cpp:

// ParticleToMesh zeros rho, then adds ghost cell contributions to the
// valid cells they overlap, including across periodic boundaries.
amrex::ParticleToMesh(*this, rho, lev,
    [=] AMREX_GPU_DEVICE (const ConstPTDType& ptd, int i,
                          amrex::Array4<amrex::Real> const& rho_arr) noexcept
    {
        const ConstParticle p = ptd[i];
        amrex::ParticleInterpolator::Linear interp(p, plo, dxi);
        interp.ParticleToMesh(p, rho_arr, 0, 0, 1,
            [=] (ConstParticle const&, int) noexcept
            {
                return q_over_vol * ptd.rdata(PIdx::w)[i];
            });
    });

The field solver sets up MLPoisson and MLMG once, in its constructor, and reuses them every step:

FieldSolver::FieldSolver (const amrex::Geometry& geom, const amrex::BoxArray& ba,
                          const amrex::DistributionMapping& dm, amrex::Real epsilon0)
    : m_geom(geom),
      m_epsilon0(epsilon0),
      m_linop({geom}, {ba}, {dm}),
      m_mlmg(m_linop)
{
    // All-periodic domain. The operator is singular; MLMG removes the mean
    // of the right-hand side to make the problem solvable.
    m_linop.setDomainBC({AMREX_D_DECL(amrex::LinOpBCType::Periodic,
                                      amrex::LinOpBCType::Periodic,
                                      amrex::LinOpBCType::Periodic)},
                        {AMREX_D_DECL(amrex::LinOpBCType::Periodic,
                                      amrex::LinOpBCType::Periodic,
                                      amrex::LinOpBCType::Periodic)});
    m_linop.setLevelBC(0, nullptr);
    m_mlmg.setVerbose(0);
}

Run (from the top of the repository, see Getting Started):

cmake --build build --target Particles_ElectrostaticPIC -j 8
cd build/Particles/ElectrostaticPIC
mpiexec -n 2 ./ElectrostaticPIC inputs

n_cell and nppc take three values; 2D uses the first two. The plotfiles plt00000, plt00050 and plt00100 contain rho, phi, the electric field and the electrons.
