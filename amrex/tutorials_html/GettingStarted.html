Getting Started

The tutorials need a C++20 compiler and, for MPI builds (the default), an MPI library. GPU builds need CUDA, ROCm (HIP) or oneAPI (SYCL). CPU builds with CMake also need FFTW (or -DAMReX_FFT=OFF, which skips the FFT tutorials). Every tutorial except the Python scripts builds with CMake or with GNU Make.

git clone https://github.com/AMReX-Codes/amrex-tutorials.git
cd amrex-tutorials

Building with CMake

From the top of the repository, CMake configures all tutorials at once. By default, AMReX is downloaded and built as part of the tutorials (a superbuild with FetchContent):

cmake -S . -B build
cmake --build build -j 8
ctest --test-dir build

Each tutorial <Topic>/<Name> is the target <Topic>_<Name>. Its executable, named <Name>, and its inputs file are placed in build/<Topic>/<Name>. The Applications have one target per problem, e.g. Applications_CNS_Sod; see their READMEs.

cmake --build build --target Base_HeatEquation -j 8
cd build/Base/HeatEquation
mpiexec -n 2 ./HeatEquation inputs

Runtime parameters can be overridden on the command line after the inputs file, e.g. ./HeatEquation inputs n_cell=64.

-DAMReXTutorials_PYTHON=ON

Test the Python tutorials (needs the amrex Python module)

-DAMReXTutorials_TORCH=ON

Build the ML tutorial (needs LibTorch)

In a superbuild, AMReX is configured with EB, FFT, particles and linear solvers enabled. Any AMReX CMake option, e.g. -DAMReX_FFT=OFF, can be passed on the command line. With an installed AMReX, the tutorials use its GPU backend. Tutorials that need a component the AMReX build does not have (e.g. EB, FFT, MPI or SUNDIALS), or that do not support the chosen dimension, are skipped with a message at configure time.

Tests

Each tutorial is registered as a CTest test that runs it with its inputs file, on 2 MPI ranks in MPI builds (the MPMD test needs 4; with Open MPI, add -DMPIEXEC_PREFLAGS=--oversubscribe if needed). Tutorials with an exact or reference answer check it and return a non-zero exit code if the error is too large. With GCC or Clang on CPUs, the tests trap floating-point exceptions (amrex.fpe_trap_invalid=1 amrex.fpe_trap_zero=1 amrex.fpe_trap_overflow=1) when the tutorials are configured with -DAMReX_TESTING=ON or AMReX is built with -DAMReX_FPE=ON.

ctest --test-dir build --output-on-failure
ctest --test-dir build -R LinearSolvers

On a GPU, AMReX preallocates 3/4 of the device memory at startup. If the test ranks share one GPU, they may run out of memory; set a smaller initial size through the AMREX_DEFAULT_INIT environment variable:

AMREX_DEFAULT_INIT="amrex.the_arena_init_size=268435456" ctest --test-dir build

Building with GNU Make

Clone AMReX next to this repository, or point AMREX_HOME to an AMReX source tree, and run make in a tutorial directory:

cd ..
git clone https://github.com/AMReX-Codes/amrex.git
cd amrex-tutorials/Base/HeatEquation
make -j8
mpiexec -n 2 ./main3d.gnu.MPI.ex inputs

The GNUmakefile sets the build options, which can also be given on the command line, e.g. make -j8 DIM=2 USE_OMP=TRUE:

Variable

Meaning

AMREX_HOME

Path to AMReX (default: amrex next to this repository)

DIM

1, 2 or 3

COMP

Compiler family: gnu, llvm, intel-llvm, …

USE_MPI, USE_OMP

MPI (default on) and OpenMP

USE_CUDA, USE_HIP, USE_SYCL

GPU backend

DEBUG

Debug build with bounds checking

TINY_PROFILE

TinyProfiler (default off); see Profiling with TinyProfiler

The name of the executable reflects the options, e.g. main3d.gnu.DEBUG.MPI.OMP.ex. make clean removes the build.

Running the tutorials

Runtime parameters come from the inputs file and the command line; arguments after the inputs file override it, e.g. mpiexec -n 2 ./HeatEquation inputs n_cell=128. See ParmParse.

The inputs files are set up so that each tutorial runs in a few seconds, also as a test in CI: small domains, few steps, and small grids. In production runs, max_grid_size and blocking_factor are usually much larger, because larger boxes mean less overhead per box and better performance, especially on GPUs.

Many tutorials write plotfiles; Viewing plotfiles lists tools that read them.

Your own project

The BuildSystems directory contains three standalone projects to copy when starting a new code: a CMake superbuild that fetches AMReX (CMakeSuperbuild), a CMake project that links to an installed AMReX (CMakeInstalledAMReX), and a GNU Make project (GNUMake).

For all AMReX build options, see Building AMReX in the AMReX documentation.
